# 建单失败时的会话状态

此说明只适用于订单 API 的主建单流程，不是支付已成功或用户已登录的证明。

- 订单参数先在本地验证。需要刷新会话时，服务先用指定出口检查连通性；预检不接受用户 Cookie、不跟随重定向。收到 403、429 或连接错误即停止，不换出口。匿名检查与认证请求不共用 Cookie 容器。
- 成功刷新的快照只放进当前进程的订单 Vault；写入发生在关闭刷新客户端和尝试建单之前。若建单失败，错误响应不包含快照。回执中的 `session_reissued_for_country` 只说明已发生重签发，不代表会话仍有效或可以导出。
- Vault 的最长保留期是 30 分钟，后续写入不续期。过期会释放 Vault 引用；重启、崩溃或切换到其他 worker 都不能恢复这份快照。这不是对 Python 进程内存的逐字节擦除承诺。
- 同一进程中，同一幂等键的并发建单被拒绝。已有订单再次提交相同幂等键只返回订单状态，不会再做结账请求。超时不等于上游未受理，不自动重放。订单号和幂等键都不是调用已保存凭证的身份凭据。
- 匿名预检、账号请求与支付请求的 HTTP 客户端按凭证范围隔离。主线适配器的普通 HTTP 超时为 15 秒（不是整个订单的总时限）。订单 Vault 不持有带认证的长连接。
- 维护前应先停止接入新订单，确认在途订单结束再重启。仅健康检查正常不足以证明已排空。离线验收应使用假适配器、独立数据目录和系统级出站网络限制。
