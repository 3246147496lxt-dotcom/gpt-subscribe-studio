# 非 Team：固定且经过核验的付款主体账单

本部署只服务一个已核验付款主体。核验由有授权的管理员在系统外完成；浏览器没有认证或修改地址的接口。账单地址不是发卡机构对某张卡所有权的证明。本规则也不授予任何税收待遇。

部署管理员通过环境变量 `GSS_VERIFIED_BILLING_FILE` 指向一个位于仓库与静态目录之外的私有普通 JSON 文件（绝对路径，权限 0600 或 0400；不得为符号链接）。文件只含 `payer_id`、`verification_ref` 和 `billing`。前两项是单一付款主体和可信核验记录的内部引用；不能是登录、支付或卡片凭证。管理员只有在核对通过后才发布此文件；撤销时移除它。不要将真实资料提供给聊天、示例、Git 或日志。

`billing` 的字段为 name、email、line1、city、state、postal_code、country；country 为支持的两位国家代码，US/CA 必须有州/省。除允许为空的州/省外须齐全。只忽略首尾空白及国家代码大小写，不猜测、不补齐、不以模板替换信息。固定地址和本次渠道所声明的账单国不一致时拒绝，不修改任何一方。

非 Team 建单、首次付款及其续接在发生渠道写入前校验。新的订单绑定核验记录；旧订单、不同主体、记录变更或声明冲突均不能用该订单继续写。撤销或更换记录后不再展示旧付款主体的地址；既有回执和只读核对不依赖重新授权。缺少可用核验配置时默认关闭新的非 Team 结账，不得退回随机地址。UI 只读展示服务端标记且完整的地址；Team 保持原流程。

能力边界：非 Team API 不再发放可编辑的托管结账链接或可继续写入的客户会话密钥。外来的支付方式标识本身不能证明账单归属，不能凭客户端另附的地址解锁。旧的 Plus 独立直付/支付方式探针入口不能建立本单核验关系，执行时停止；已经在其他系统发放的链接不在本服务的撤销能力内。
