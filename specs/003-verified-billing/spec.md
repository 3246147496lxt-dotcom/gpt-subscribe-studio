# 非 Team：固定美国免税账单，出口自由

本部署只服务一个固定付款主体。非 Team 账单地址与账单国家是**固定值**：美国免税州
（AK / DE / MT / NH / OR 之一）。出口代理不固定，可以按订单选择任意支持的地区，
也可以在网关侧轮换 SID / IP；出口不参与账单地址生成，也不授权修改账单。

核验由有授权的管理员在系统外完成；浏览器没有认证或修改地址的接口。账单地址不是
发卡机构对某张卡所有权的证明。本规则也不授予任何税收待遇；是否免税由 Stripe /
上游按地址计算，本服务只保证提交的地址始终是同一份。

## 配置

按优先级读取：

1. `GSS_FIXED_BILLING_FILE`：固定美国免税地址（推荐；设置后优先）。
2. `GSS_BILLING_PROFILES_FILE`：按币种/国家的多份已核验资料（version 2）。
3. `GSS_VERIFIED_BILLING_FILE`：旧的单份已核验付款主体文件。文件只含
   `name / email / line1 / city / state / postal_code / country` 七个字段，
   `country` 必须是 `US`，`state` 必须是免税州。

三者都必须是仓库与静态目录之外的**绝对路径**普通 JSON 文件，权限 `0600` 或
`0400`，不得为符号链接。地址只允许首尾空白和州/国家大小写差异，不猜测、不补齐、
不以模板替换。缺少可用配置时，新的非 Team 结账/付款一律停止；不会退回随机地址。

`scripts/setup_fixed_us_billing.py` 可按参数生成该文件，并输出需要导出的环境变量。
仓库内置的 `gss_core.fixed_billing.DEFAULT_ADDRESS` 只是固定样例，仅在未配置
`GSS_FIXED_BILLING_FILE` 的展示/兜底路径使用；正式订单仍要求上面三种配置之一。

## 出口与账单解耦

- 建单请求的 `exit_country` 自由：显式出口 → Session 签发地 → 已配置网关地区 →
  账单国兜底。出口变化只影响代理、币种、语言/时区和会话重签发，不改账单。
- 建单 `billing_details.country` 使用固定账单国（US），`currency` 仍随出口。
  这与网页端抓包一致：`billing_details = {country: "US", currency: "JPY"}`，
  结账地址为美国免税州，税额为 0。
- 支付确认、税费重算、payment method 的 billing details 全部使用固定地址。
- 上游响应里如果回显的是**当前选中的出口国**，不视为地址冲突；回显任何其它国家
  仍触发 `BILLING_COUNTRY_MISMATCH`，在提交付款前停止。
- 需要恢复旧的“出口必须等于账单国”行为时，设置
  `GSS_REQUIRE_EXIT_BILLING_MATCH=1`（严格模式）。默认关闭。

## 订单绑定

非 Team 建单、首次付款及其续接在发生渠道写入前校验。新的订单绑定核验记录；旧订单、
不同主体、记录变更或账单字段冲突均不能用该订单继续写。出口字段不属于账单断言，
因此允许在订单生命周期内保持不变或按网关重试策略轮换 SID。撤销或更换记录后不再
展示旧付款主体的地址；既有回执和只读核对不依赖重新授权。

UI 只读展示服务端标记且完整的地址；Team 保持原流程。

## 能力边界

非 Team API 不再发放可编辑的托管结账链接或可继续写入的客户会话密钥。外来的支付
方式标识本身不能证明账单归属，不能凭客户端另附的地址解锁。旧的 Plus 独立直付/支付
方式探针入口不能建立本单核验关系，执行时停止；已经在其他系统发放的链接不在本服务
的撤销能力内。
