# 非 Team：建单响应丢失后的原单恢复

同一标签页内，一笔非 Team 购买对应一个随机幂等键。首次提交前将键写入 sessionStorage；若没有可靠的存储，不得发出建单请求。请求中断、并发、重载页面、修改表单和收到冲突均不是开始另一笔购买的证据。未知结果只能用原键及相同输入请服务端核对（不自动提交）；用户须自行重新提供 Session。

一旦得到订单 ID，以它替换随机键；再次打开只按 ID 查询，不重建、不自动付款。只有用户明确确认开始另一笔购买才解除绑定；这不会撤销原订单。关闭标签页或清理站点存储后的恢复不属于此保证。Team 继续采用原有流程。

浏览器只保存随机键或订单 UUID，不保存 Session、卡信息、请求体、指纹或订单回包。沿用既有 HTTP 契约，不新增按键查询订单的接口。

验收：断开第一份成功回包后再次点击以及刷新后重试均须复用原单；两次纯建单不能扣款，随后显式支付同单再重提最多扣一次。存储不可用时请求计数为零，已知 ID 查询失败也不得回退建单。使用禁网假渠道，不发起真实支付。
